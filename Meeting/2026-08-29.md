## 이번 미팅의 출발점 — Kay가 겪은 문제

- **한 집에 가족이 4명이면 리드에서는 아무것도 못 한다.** 리드로 아버지 한 명이 들어오고, 나머지 가족 정보를 받아도 **리드에는 가족을 연결할 방법이 없음** → 어쩔 수 없이 Contact로 Convert한 뒤 거기서 다시 정보를 치고 가족을 연결.
- 결과적으로 **같은 정보를 리드에 한 번, 컨택트에 또 한 번** 입력하게 됨. Kay: **"리드는 진짜 인포메이션 한 번 딱 받는 것밖에 할 게 없다. 그럴 거면 차라리 처음부터 컨택트로 받는 게 낫다."**
- 한 집이면 참겠는데 **세 집·네 집이 한꺼번에 들어오면** 감당이 안 됨 → **"이건 안 되겠다"**는 결론으로 이번 회의 시작.
- 커머셜·그룹헬스도 같은 문제. **회사 정보를 넣을 곳이 리드에 없어서** 리드인데도 억지로 Convert → Contact ↔ Company 연결을 하고 있었음.

## 결정 사항 (액션 아님 — 이해/합의)

- **🔴 리드는 리드에서 끝낸다 — Kay 방식으로 확정.** 이번 미팅 최대 쟁점.
  - 성화 주장: 그 정도 정보(메디케어 번호·주치의·SSN 등)를 주고받는 단계면 **이미 리드가 아니라 컨택트**다. 리드에 전부 넣으면 **리드의 원래 성격을 못 쓰고 오히려 이중 작업**이 된다. → 컨버트 후 컨택트에서 관리하고, 중간에 이탈하면 Inactive 처리하자.
  - Kay 반론: **"지금 포인트가 서로 달라요. 리드가 어떤 성격이고 컨택트가 어떤 성격인지가 중요한 게 아니라, 어디서 이 일을 한꺼번에 처리하기 가장 좋은가가 중요하다."** 견적 단계에서 이미 상담 내용·의사·플랜 정보를 다 받아 적고, 그 상태로 **Status로 진행 단계를 관리**해야 그 다음 일이 수월하다. 양쪽(리드+컨택트)을 동시에 보는 게 제일 힘들다.
  - **→ 성화 수용.** "현재 개발된 것을 기점으로 보면 그게 가장 효과적일 것 같습니다." **리드에 필드를 만들고, Convert 시 Contact로 넘어가도록 매핑을 추가**하는 방향으로 확정.
- **리드/컨택트의 원칙 정의(참고용).** 리드 = 아직 K2 손님이 아닌 사람, 컨택트 = 손님이거나 손님이었던 사람. 리드는 원래 **Contact 전용이 아니라 Account·Opportunity로도 Convert되는 오브젝트**다. 지금까지는 Contact 전용으로만 써 왔음.
- **Interested Insurance는 다중 선택 → 단일 선택으로 바꾼다.** Kay: **"두 개를 선택해서 들어온 손님이 지금까지 없었어요."** (원래 다중으로 만든 이유는 Kay가 초기에 "여러 보험에 관심 가질 수 있다"고 했기 때문 → 실사용에서 반증됨.)
  - 지금 화면이 복잡한 이유가 바로 그것: 다중 선택이라 **Dual Listbox(Available/Selected 박스)** 로 보임. Kay: **"이 박스는 써 본 사람만 알지, 안 써 본 사람은 솔직히 어려워요. 나도 처음 봤을 때 뭘 하라는 건지 몰랐어요."**
- **리드폼에서 보험 선택 자체는 없앨 수 없다.** 어떤 보험에 관심 있는지는 당연히 물어야 함. 바뀌는 건 **"박스 → 드롭다운"** 이지 질문의 유무가 아님.
- **Lead Record Type은 하나만 추가한다 — `Commercial / Group Health`.** 🔴
  - 논의 중에는 `Auto/Home`도 만들자고 했으나, Kay 결론: **"Auto/Home은 그냥 Others 쓰면 돼요."** 관심 분야 선택지에는 Auto/Home이 있어야 하지만, **리드 Record Type은 Others로 들어와도 됨.**
  - 즉 최종: `Health` / `Medicare` / `Others` / **`Commercial · Group Health`(신규)** 4종.
  - Commercial·Group Health를 하나로 묶는 근거(Kay): **"사람은 있지만 그 사람을 통해서 회사 정보가 같이 들어오는 리드"** 는 성격이 같다.
- **Record Type은 그대로 유지한다(픽리스트로 대체하지 않음).** Kay가 "왜 이렇게 나눴지?"라고 물었고, 성화 답: **Record Type별로 받아야 하는 정보가 달라서 페이지 레이아웃을 다르게 보여주려고.** 다시 하나로 합치면 **그 보험에 필요 없는 필드가 화면에 뜨는 문제**가 생김. → 유지.
- **기업용 리드폼은 따로 만들지 않는다.** 성화 제안(회사 전용 리드폼 링크를 하나 더 만들어 회사 주소·직원 수까지 손님이 직접 입력)에 Kay: **"지금은 내가 넣을 수 있는 곳만 있어도 될 것 같아요."** → **필드만 추가**, 폼 분리는 보류.
  - 단 성화 주의사항: **현재 리드폼은 사람(개인)만 생성한다.** 기업 리드는 Salesforce 안에서 **New로 직접 생성**해야 함. (실제 운영: 오너/매니저 개인은 리드폼으로 받고, 회사 정보는 Kay가 그 리드에 직접 입력.)
- **가족 연결이 필요한 건 건강보험과 메디케어뿐.** 🔴 Kay: 집·자동차는 가족 정보를 받을 필요가 없고, **그룹헬스는 회사에서 직접 받기 때문에 애초에 이 폼을 쓸 일이 없음.** → **Health · Medicare 2개 Record Type에만** 가족 기능 적용.
- **메디케어 부부 손님도 연결이 되어야 한다.** (8/22 "부부 리드는 따로 작성" 결정을 **이번에 뒤집음** — 리드 단계 가족 연결 기능이 생기므로.)
- **리뉴얼(Opportunity)은 그룹헬스에만 쓴다.** Kay: 집·자동차는 건수도 많고 리뉴 내용도 많아 **"그거까지는 정말 못 하겠다"** → Auto/Home은 지금처럼 **Policy 위의 퀵 리뉴얼 버튼**만 사용, 커머셜도 굳이 관리 안 함. **그룹헬스만 Renewal로 관리.**
- **리드폼 UI를 좀 더 모던하게 다듬는다.** Kay: **"이 모양 자체가 좀 더 세련되면 좋겠다."** 성화 설명: 지금 세로로 길게 보이는 건 **모바일 폼 기준**이라서. Kay 확인: **"맞아요, 접속하는 사람 대부분이 모바일이에요."** → 모바일 우선은 유지하고 스타일만 현대화.

## 검증 방법 (개발 항목 구현 시)

- **A1/A2 (가족):** 리드폼에서 "가족 있음" → 4명 입력 → Submit 시 **리드가 정확히 4건** 생성되고 **서로 가족 관계로 연결**되는지. **주소·전화·이메일 공통 정보가 4건에 올바르게 복사**되는지(그리고 폼에서는 한 번만 물었는지). 그 4건을 Convert했을 때 **Contact 쪽 가족 관계가 그대로 유지**되는지(중복 관계 레코드가 생기지 않는지). Health·Medicare 외 Record Type에서는 **가족 UI가 아예 안 뜨는지.**
- **A3 (단일 선택):** 폼에 드롭다운이 뜨고 **한 개만 선택 가능**, **미선택 시 Submit 차단**되는지. 각 값 → Record Type 매핑이 의도대로인지: `Medicare`→Medicare, `Health`→Health, **`Group Health`·`Commercial`→Commercial·Group Health**, `Auto/Home`·`Life`·`Other`→Others. **기존 다중값 리드 데이터가 단일 전환 시 깨지지 않는지**(값이 2개 이상 들어있는 기존 레코드 사전 조사 필수 — restricted picklist라 변환 실패 가능).
- **A4 (기업 리드):** `Commercial · Group Health` Record Type으로 New 생성 시 **회사 정보 필드가 보이고**, 다른 Record Type에는 **안 보이는지.** Account로 Convert 시 회사 정보가 Account에 매핑되는지.
- **A5 (메디케어 필드):** 리드에서 Primary Doctor 선택 시 **Vendor Record Type Account만 검색**되는지. Convert 후 **Contact의 같은 필드에 값이 그대로** 넘어갔는지(특히 Lookup Id 보존). **리드폼(게스트 화면)에는 이 필드들이 노출되지 않는지.**
- **B2 (리뉴얼):** New Insurance를 Draft로 두었을 때 **기존 폴리시가 Inactive로 강제 전환되지 않는지**, Renewal Stage가 `Quote Email`로 유지되는지, 그리고 **그 조합이 리스트뷰/리포트에서 눈에 띄게 잡히는지.**
- **B4 (템플릿):** 리뉴얼 레코드에서 발송 시 **그룹 이름·Period·다음 텀 가격이 실제로 치환**되는지, **빈 필드일 때 깨지지 않는지.**
